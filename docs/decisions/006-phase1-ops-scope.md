# 006 — Phase 1 운영 범위: OS 네이티브 데몬 관리, 인증 없음

- **날짜:** 2026-10-11
- **관련 코드:** `deploy/macos/*.plist`, `deploy/windows/*-service.xml`

## 상황 (Context)

두 가지가 미결이었다: (1) 데몬 자동 재시작을 어떤 메커니즘으로 구현할지, (2) 웹 어드민
인증을 Phase 1부터 넣을지 (가정용이라도 외부 포트포워딩 시 노출 위험 있음).

## 검토한 대안

**재시작 메커니즘**
1. OS 네이티브 (macOS: launchd, Windows: 서비스 매니저) — 플랫폼 표준, 추가 의존성 없음.
2. 자체 supervisor 프로세스 — 플랫폼 중립적이지만 별도 구현/유지보수 필요.

**인증**
1. Phase 1부터 도입 — 외부 노출 시 더 안전하지만 지금 범위를 넘는 작업.
2. Phase 1은 인증 없음, Phase 2로 유지 — 가정용 로컬 네트워크 기준으로 범위를 좁힘.

## 결정

재시작: 옵션 1 (macOS launchd / Windows 서비스 매니저).
인증: 옵션 2 (Phase 1 인증 없음, 기존 로드맵 유지).

## 근거 (왜)

사용자 확인. 재시작은 플랫폼 표준 메커니즘을 쓰는 게 "일반적인 소프트웨어공학" 원칙과
맞고 추가 구현 부담이 없다. 인증은 지금 당장 고려 대상이 아니라고 명시적으로 확인함 —
기존 메모리의 Phase 2 계획과 일치하므로 변경 없음.

## 재검토 조건

사용자가 공유기 포트포워딩 등으로 외부 인터넷에 웹 어드민을 노출하기로 결정하는 순간,
인증 도입을 Phase 1로 끌어와야 한다 — 그 전에는 로컬 네트워크 내부 접근만 가정한다.

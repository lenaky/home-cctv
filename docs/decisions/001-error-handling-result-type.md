# 001 — 에러 처리: 직접 구현한 Result<T,E> 사용

- **날짜:** 2026-10-11
- **관련 코드:** 전체 `domain/ports/*`, `application/*_usecase.h` 시그니처 전부

## 상황 (Context)

CLAUDE.md 제약상 "에러는 전부 명시적 반환"이 필수다. C++20 기준으로 예외 대신 쓸 명시적
에러 채널 타입을 뭘로 할지 결정이 필요했다. `std::expected`는 C++23이라 아직 쓸 수 없다.

## 검토한 대안

1. 직접 구현한 `Result<T, E>` — 의존성 추가 없음. 유지보수(연산자 오버로드, monadic 체이닝
   등)는 직접 부담.
2. `tl::expected` (단일 헤더 서드파티) — `std::expected`와 API가 유사해 C++23 전환 시
   마이그레이션이 쉬움.
3. `Boost.Outcome` — 이미 Boost.Asio를 쓰므로 생태계 일관성은 있으나 무겁고 러닝커브 있음.

## 결정

직접 구현한 `Result<T, E>` 사용.

## 근거 (왜)

사용자가 명시적으로 선택. 외부 의존성을 하나 더 늘리지 않는 것을 우선시했다. 필요한 기능
(값/에러 보관, 성공 여부 확인, 값 꺼내기)이 작아서 직접 구현 비용이 크지 않다고 판단.

## 재검토 조건

monadic 체이닝(`and_then`, `or_else` 등)이 코드베이스 전반에 필요해지는 시점에, 직접
구현의 유지보수 비용이 `tl::expected` 도입 비용을 넘어서면 재검토.
